## 0.3.1 (2026-10-14)
- scripts/inference-proxy.js: a signed send that did not land now stays counted until it either lands or a different block is confirmed at its height, and the proxy forces the second outcome itself by publishing a change block at that height (same balance, same representative, nothing moves; the send's work is reused). Until now a refused `exact` call (`not_broadcast_refused`) and a send the node rejected (`not_broadcast`) were uncounted at once although the signed block stayed valid for as long as the frontier did not move, so a seller holding a refused payload, or a node that took a broadcast whose reply was lost, could put one per-call amount per frontier on the chain outside the cap; and `unknown` entries were uncounted on a single "not found" read. The 0.3.0 design note said so. Each payment entry now carries `previous`, `height`, `work`, `counted` (inside the cap right now), `final` (settled for good) and `invalidated_by` (the change block); settlement runs before every decision, at start-up (a send signed by a run that died before broadcasting is retired) and right after a refusal, with up to three looks a few hundred milliseconds apart so that on the live network the amount is usually released inside the refusing call. If the change block cannot be published the amount stays counted against the cap and is retried. Refusals `broadcast_failed` and `not_served_after_payment` report `counted` and `invalidated_by`. The refused payload is no longer kept in the state file: a refused call is a new quote and a new send, never a re-presentation. Verified on the live network first: a change block with an unchanged representative on the proxy's own test account was accepted and confirmed as subtype `change` (block 1D8C2B744736B75892EE91EC0234A3525C0F5E56A2EF45F44E63334839D0627C, 2026-10-14 08:07 UTC). Entries written by 0.3.0 and earlier carry no height and are left as they are.
- scripts/client-x402.js: `NANO_SAVE_PAYLOAD=<path>` (off by default) writes the `PAYMENT-SIGNATURE` header value after the call, with the url, method, block hash, final status and the last `X-Nano-Represent` token, mode 600, so the same payment can be re-presented later to a route that takes the purchase header as proof (Subnano's asset download, 2026-10-08). Until the block is on the chain the file is a spendable signed send, hence opt-in.
- test/inference-proxy.js: 30 cases. The mock node accepts `change` blocks and reports heights and a confirmed frontier; the mock door can keep the signed block without broadcasting. New: a seller that keeps the block and refuses, then cannot cash it after the change block took its height (`Fork`), nothing kept in the state file, work reused; a rejected broadcast retired the same way; a retirement the node refuses three times that stays counted, blocks the cap at the next call and is released at the one after; a `signed` entry from a dead run settled at start-up.
- references/inference-proxy.md: the "what did not land" paragraph, the three entry fields, the test list.

## 0.3.0 (2026-10-11)
- scripts/inference-proxy.js: `PROXY_KEY` (16+ characters) is required at start, and every `/v1/*` request must carry it as `Authorization: Bearer <key>` or `x-api-key: <key>`; a request without it, or with a wrong one, is refused 401 `proxy_key` before the door is reached, before it is counted as a call and before anything is signed (constant-time compare on a hash). Until now any key was accepted and dropped, so every process on the machine, and every web page the operator's browser opened, could spend through the proxy inside the cap: the proxy binds 127.0.0.1, but loopback is shared. ClawHub's scanner said so in its summary of 0.2.3 ("its local payment proxy can spend wallet funds from unauthenticated local requests"); it was right. Breaking for existing installs: set `PROXY_KEY` and give the runtime the same value as its API key (the OpenClaw recipe's `apiKey` field).
- scripts/inference-proxy.js: two more refusals on every route, before the key is read: a `Host` header that is not a loopback name (`127.0.0.1`, `localhost`, `[::1]`, port optional) is refused 403 `host_not_loopback` (a page that rebinds its DNS to 127.0.0.1 arrives with its own host name), and any request carrying an `Origin` header is refused 403 `browser_origin` (a browser sets one on every cross-site request, including the no-preflight POSTs a page can send to loopback; nothing that uses this proxy legitimately sends one).
- test/inference-proxy.js: 27 cases. New: five keyless or wrong-key shapes refused 401 with nothing at the door, nothing signed and `calls` unchanged, then the key in `x-api-key` paid and, as before, absent at the door; a rebound Host and a browser Origin refused 403 on `/v1` and on `/_nano/state`, a text/plain no-credential browser POST refused, the four loopback Host spellings accepted and a paid call through `localhost`. Start-up refusal covers a missing and a short `PROXY_KEY`. Node's fetch replaces a caller-set Host header, so those cases use `http.request`.
- SKILL.md, references/inference-proxy.md: the setup line exports `PROXY_KEY`, the recipe's `apiKey` is that value, step 0 of the decision list, the three codes, and a "not a wall between users" line.
