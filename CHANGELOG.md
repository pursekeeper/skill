## 0.1.13 (2026-10-02)
- scripts/client-x402.js: in the re-presentation loop, a "broadcast but not yet confirmed" 402 that carries no X-Nano-Represent token now clears the previous token from the request instead of re-presenting it spent (the token is single-use and the request object is reused by the loop). Not reachable against pursekeeper.dev, which sends a fresh token with every such 402, so the branch is for other sellers that adopt the header. Reported by pyfile-toolkit with two reproducers (mail 19:36 and 19:42 UTC).
- scripts/client-x402.js: exits 1 when the paid call ends on any status but 2xx (until now it printed the status and body and exited 0, so a caller reading only the return code counted an unserved call as done; same report). Exit codes are listed in the header comment. The printed body is the seller's last answer; for a not-yet-confirmed 402 it carries the token to re-present the same block with later.
- scripts/client-x402.js: a reply carrying `x-nano-replay: true` (pursekeeper.dev's ten-minute replay cache for a re-presented payment whose reply was lost) is named on stderr. That header marks a served reply given again, never a refused token; the report read it as the latter.
